# App Theme — Workflow

> Task type: cross-cutting refactor
> Stack: AdonisJS
> Generated output: `.adonisjs/` is written only by codegen. Never edit it by hand; keep its changes with the completed task.

## Summary

Replace the stock `neutral` Astryx theme with a local, built `quran` theme that extends it: a generated OKLCH palette (deep green accent `#0F6B4F`, warm sand neutrals) for light and dark, Figtree body with Fraunces headings, softer corner radii (4/8/10/20px), slightly calmer motion, warm sand-tinted shadows, quieter borders, palette-matched status colors and overlays, roomier controls, and a custom `Text type="arabic"` variant set in Amiri. Fonts are self-hosted via `@fontsource`, and every place that renders Arabic switches to the new variant. The leftover AdonisJS starter branding (mark, name, `<title>`, auth panel and home page copy) becomes Quran Reader, with a matching favicon and browser `theme-color`.

## Invariants

- The color-mode flow is untouched: `light` / `dark` / `system` from the `app_theme` cookie, the Edge shell's pre-paint `color-scheme`, `useThemePreference()`, and `<Theme mode={preference}>` in `AppProviders`.
- `AppProviders` keeps reading `themes[defaultThemeSlug]` from the generated `astryx-themes.ts`; the only thing that changes is which theme that module records as default.
- No route, controller, prop, transformer, or component API changes. Browser tests keep passing (`data-testid="bismillah"` stays on the bismillah stack). The only test edits are the copy and label assertions in `navigation.spec.ts` (Step 10).
- Link labels that other tests click keep their exact text: "Read the Quran", "Get started" and "Sign in" in Main navigation, and "Back to home".
- No raw hex/px in app code (`inertia/`); colors and font stacks live only in the theme source. The only exceptions are `public/favicon.svg` and the `theme-color` meta tags, which can't read tokens and copy their values from palette stops.
- The `--spacing-*` scale and every page frame stay unchanged.
- `@astryxdesign/theme-neutral` stays installed — the `quran` theme source extends it.

## Blast radius

- New: `src/themes/quran/` (`palette.config.json`, `tokens/quran.palette.ts` + receipt, `quranTheme.ts`, `quranTheme.doc.mjs`, built `quran.css` / `quran.js` / `quran.d.ts` / `quran.variants.d.ts`).
- Regenerated by the CLI: `astryx-themes.ts`.
- Modified: `package.json` / `package-lock.json` (fontsource deps), `inertia/app.tsx` (font imports), `.oxlintrc.json` / `.oxfmtrc.json` (ignore generated theme output), `inertia/components/quran/ayah_item.tsx`, `inertia/components/quran/surah_heading.tsx`, `inertia/components/bookmarks/bookmark_list_item.tsx`, `inertia/pages/quran/show.tsx`, `inertia/components/brand/logo.tsx`, `inertia/components/auth/auth_layout.tsx`, `inertia/pages/marketing/home.tsx`, `resources/views/inertia_layout.edge`, `tests/browser/navigation.spec.ts`.
- New: `public/favicon.svg`.
- Every page's look changes: colors, type, corner radii, shadows, borders, control heights, transition timing. The brand mark and name change everywhere. No behavior or page frame changes.

## Out of scope

- A runtime switcher between several themes — one default theme only.
- Per-component `components` overrides (TopNav, Card, Button, ListItem, Toast, Dialog, …) — offered and not chosen; they follow the tokens instead.
- The `--spacing-*` scale — changing it would reflow every layout, and `auth_layout.tsx` sizes its columns from it.
- Text selection color — Astryx has no token for it, and raw CSS is forbidden.
- Data-viz and syntax-highlighting tokens — nothing in the app renders charts or code.

> For new complete palettes, generate and review a committed palette module, then import its `palette` export and reference stable stops from semantic tokens. This keeps mapped roles coherent when the accepted palette is regenerated; generation itself does not rewrite the theme.

  - `npx astryx theme palette generate src/themes/quran/palette.config.json --out src/themes/quran/tokens/quran.palette.ts --preview tmp/quran.palette.html`

### Step 2 — Theme source and descriptor

Reads: astryx docs author-a-theme, astryx docs use-a-theme, astryx docs typography/font-setup

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/author-a-theme.doc.mjs:17-18

> Use an installed built theme as the base for ordinary customization. Import it into your source and pass it as `extends` to `defineTheme({extends: importedTheme, ...})`. Build the result, then add the local slug. Only eject when you need to own and maintain a full source fork.

> A local theme is a folder in `src/themes/<slug>/` holding a `<name>Theme.ts` source that exports `<name>Theme`, and a same-stem `<name>Theme.doc.mjs` descriptor that `theme add` reads. The stem must be a valid export name, so a hyphenated slug drops the hyphen: `brand-dark` lives in `src/themes/brand-dark/brandDarkTheme.ts` exporting `brandDarkTheme`, beside `brandDarkTheme.doc.mjs`. The descriptor's `name` is the folder's slug, and it must declare its type or `theme add` and `theme list` refuse it. {@command docs authoring theme-doc} lists every field.

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/author-a-theme.doc.mjs:57, :65

> 'tokens', 'Base tokens are copied first, then child tokens override on top.'

> 'typography, radius, color', 'Child config replaces base entirely (these are scale inputs, not additive).'

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/author-a-theme.doc.mjs:75, :78-79, :85, :88

> The `components` field in defineTheme uses semantic component keys and style keys, not raw CSS selectors. Use `base` for all instances, `variant:value` or `stateName` for specific props/states, and let the theme pipeline choose the underlying selector. For raw external CSS escape hatches, prefer the data-attribute selector surface documented in {@link generic:styling-advanced}.

> Do: 'Write standard CSS properties (borderRadius, padding); the pipeline expands them into internal vars.', 'Set public CSS vars directly when no standard property equivalent exists.'
> Don't: 'Set private CSS vars (prefixed --_) directly. Use standard CSS properties instead. `{@command theme build}` will error.', 'Set a public CSS var the component does not define. It compiles to CSS that never applies, and the build does not warn. Take the names from `{@command component <Name>}`.'

> Themes can add new prop values to any component. Any `prop:value` key where the value isn't a built-in gets treated as a new variant. Use `{@command theme build}` to generate TypeScript augmentations for type safety.

> Custom variants only work when the theme that defines them is active. The component's variant map is extended via module augmentation, with no changes to the component source needed.

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/use-a-theme.doc.mjs:130

> Use [light, dark] tuples in token values for automatic mode switching. Use mode='system' (default) on Theme to follow OS preference.

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/tree/font-setup.doc.mjs:89

> Always pair a webfont with a real fallback stack (metric-similar system fonts plus a generic) so text stays readable before the font loads and wherever it never does: defineTheme({typography: {heading: {family: 'Fraunces', fallbacks: 'Georgia, serif'}}}).

#### Decision

- `src/themes/quran/quranTheme.ts` (new) — exports `quranTheme = defineTheme({ name: 'quran', extends: neutralTheme, ... })`, with `neutralTheme` imported from `@astryxdesign/theme-neutral` (theme source only — this file is build input, never imported by app runtime code).
  - `tokens`: re-point every `--color-*` role that `node_modules/@astryxdesign/theme-neutral/src/neutralTheme.ts` maps from its `neutral` family or from `blue` as accent, using the same stops neutral uses, but from `palette.neutral` (now sand) and `palette.emerald` (accent: `--color-accent`, `--color-accent-muted`, `--color-text-accent`, `--color-icon-accent`, `--color-on-accent`, focus ring). Every value is a `[light, dark]` tuple of palette stops — no literal hex. Roles neutral maps from status families stay inherited.
  - `typography`: child config replaces neutral's entirely, so restate all of it — `scale: {base: 14, ratio: 1.2}`; `body: {family: 'Figtree Variable', fallbacks: 'Figtree, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif'}`; `heading: {family: 'Fraunces Variable', fallbacks: 'Fraunces, Georgia, "Times New Roman", serif', weights: {3: 'bold', 4: 'bold'}}`; `code` copied from neutral. The `Variable` family names are what the `@fontsource-variable/*` packages register (Step 5); confirm them from each package's CSS before building.
  - `components.text['type:arabic']`: a new `Text` variant — `fontFamily: "Amiri, 'Noto Naskh Arabic', 'Times New Roman', serif"`, `fontSize: 'var(--font-size-2xl)'`, `lineHeight: 2.2` (Arabic diacritics need generous leading), `fontWeight: 'var(--font-weight-normal)'`. Standard CSS properties only; check `npx astryx component Text` for any extra public vars before using one.
  - Neutral's `adaptations` (coarse-pointer type scale) are inherited — do not redeclare.
- `src/themes/quran/quranTheme.doc.mjs` (new) — the `ThemeDoc` descriptor: the `/** @type {import('@astryxdesign/cli/authoring').ThemeDoc} */` comment over a single default export `{ type: 'theme', name: 'quran', displayName: 'Quran', description: 'Deep green on warm sand, Fraunces headings, Amiri for the Arabic.', maintained: false }`, and nothing else.

### Step 3 — Shapes and motion

Reads: astryx docs author-a-theme

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/author-a-theme.doc.mjs:39

> Explicit token overrides always take precedence over scale-generated values, token by token.

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/author-a-theme.doc.mjs:46, :64

> 'motion', 'Every --duration-* token, --ease-entrance and --ease-move (tempo also times the touch springs)', 'tempo? (0.75–1.5), character? (crisp|standard|expressive); and/or a duration scale: fast (ms), medium (ms), ratio, slow?, easing?. The scale wins over tempo for the durations it sets, and explicit tokens win over both. Fixed whatever the knobs say: drags and momentum, rubber band, keyboard, press onset/cancel/flash, hover intent, gesture thresholds, Spinner/Skeleton loops, the 200 ms Reduce Motion cap. See {@link generic:motion}.'

> 'motion', "Field by field: the child's `fast`, `medium` and `ratio` regenerate the fast and medium duration tokens; `slow` and `easing` left unset keep the base theme's tokens, so an inherited slow band stays at the base's ratio. Each knob (`tempo`, `character`) the child leaves unset keeps the base's."

#### Decision

- `src/themes/quran/quranTheme.ts` (modified, same file as Step 2)
  - **Shapes — soft and bookish.** Neutral sets its radii as _explicit tokens_ (`--radius-inner` 0.375rem, `--radius-element` 0.625rem, `--radius-container` 0.75rem, `--radius-page` 1.75rem). Inherited explicit tokens beat any scale-generated values, so a `radius: {base, multiplier}` config would silently do nothing. Override the tokens directly in `tokens`: `--radius-inner: '0.25rem'` (4px), `--radius-element: '0.5rem'` (8px), `--radius-container: '0.625rem'` (10px), `--radius-page: '1.25rem'` (20px). Never touch `--radius-none` or `--radius-full` (fixed by Astryx).
  - **Motion — calmer.** Neutral sets a duration scale `{fast: 125, medium: 300, slow: 700, ratio: 0.75}`, and a scale beats `tempo`, so `tempo` alone would not slow anything. Set the scale about 1.2× slower: `motion: {fast: 150, medium: 360, slow: 840, ratio: 0.75, character: 'standard'}`. The 200 ms Reduce Motion cap stays fixed.
  - No layout, spacing, shadow, or border changes. Neutral's `components` overrides are inherited untouched.
- Verify after the Step 6 build: `quran.css` carries the four radius values and the new `--duration-*` values.

### Step 4 — Surface, status, focus and control tokens

Reads: astryx docs author-a-theme, astryx docs tokens

Harness rules: see Step 1 (design-system.md:15, CLAUDE.md:24-25). Astryx rules: see Step 2 (author-a-theme.doc.mjs:57 — child tokens override base tokens) and Step 3 (author-a-theme.doc.mjs:39 — explicit tokens win).

#### Decision

- `src/themes/quran/quranTheme.ts` (modified, `tokens` block). Every value comes from the palette (`palette.neutral`, `palette.emerald` and the status families), as a `[light, dark]` tuple or a `light-dark(...)` string built with a `withAlpha(color, 'NN')` helper like neutral's. No literal hex or rgba. Take the full token list from `npx astryx docs tokens/tokens-color` and neutral's `tokens` block.
  - **Elevation (`--shadow-low`, `--shadow-med`, `--shadow-high`).** Keep neutral's offsets, blur radii and dark-mode white rim inset, but tint the drop colors with a deep sand stop (about `palette.neutral.light[10]` at neutral's same alpha levels) instead of pure black. Shadows read warm on sand surfaces.
  - **Input state rings (`--shadow-inset-hover`, `--shadow-inset-selected`).** Neutral builds these from `blue`; re-point them to `palette.emerald` at the same stops and alpha (`'4D'`, `'80'`). Leave `--shadow-inset-success/-warning/-error` on their status families.
  - **Borders and dividers (`--color-border`, `--color-border-emphasized`, `--color-track`, `--color-skeleton`).** Map them from sand stops one step lower in contrast than neutral uses, for quieter hairlines on ayah lists. Keep `--border-width` at 1px.
  - **Focus ring.** `--focus-outline-color` already resolves to `var(--color-accent)` and so becomes emerald automatically; don't redeclare it. Keep `--focus-outline-width` 2px and `--focus-outline-offset` 3px. Check visually that emerald stays visible on sand in both modes.
  - **Overlay and scrim (`--color-overlay`, `--color-overlay-hover`, `--color-overlay-pressed`, `--color-background-muted`, `--color-neutral`, `--color-shadow`).** Re-point them from neutral's blue-gray base to sand stops at the same alpha.
  - **Status colors (`--color-info|success|warning|error` with `-muted`, `on-`, and the `--color-*-blue|green|yellow|red|…` family roles).** Map them from the quran palette's own status families, at the stops neutral uses, so they come from the same recipe as the warm neutrals. Map `info` from `teal`, not `blue`, so it doesn't clash with the green accent. `success` stays on `green`, which must stay visibly distinct from the emerald accent; if the Step 1 preview shows them too close, shift the `green` seed toward yellow-green and regenerate.
  - **Control sizes.** Set `--size-element-sm: '2rem'`, `--size-element-md: '2.25rem'`, `--size-element-lg: '2.5rem'` (32/36/40px, up from 28/32/36) for calmer, easier-to-hit controls.
- Deliberately unchanged:
  - **The `--spacing-*` scale.** `auth_layout.tsx` sizes its columns from `--spacing-8` / `--spacing-4` (the `COLUMN_MIN_WIDTH` comment), and every page's gaps come from it, so a global change would reflow layouts.
  - **`--duration-*`** (set in Step 3).
  - **Data-viz and syntax tokens.** The app has no charts or code blocks.
  - **Text selection color.** Astryx has no token for it, and CLAUDE.md forbids raw CSS.

### Step 6 — Build and adopt the theme

Reads: astryx docs author-a-theme, astryx docs use-a-theme

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/author-a-theme.doc.mjs:127

> The `__built: true` flag tells Theme to skip runtime `<style>` injection; the CSS file handles it. Load the generated CSS wherever you load the module.

#### Astryx rules — verbatim, node_modules/@astryxdesign/cli/assets/docs/use-a-theme.doc.mjs:38, :189-191, :199-202

> `theme add` records an installed package theme and regenerates `src/astryx-themes.ts` or `.js` with its built module, production CSS, and optional font CSS. In a project without `src`, the module is at the project root. The first imported theme becomes the default. `theme use <slug>` changes that default, and `theme remove <slug>` removes a non-default theme.

> Do: 'Use `theme add` for production apps; it wires the built module and CSS.', 'Import `themes` and `defaultThemeSlug` from the generated module once, and keep that wiring in development too.', 'While you edit a local theme, run `{@command theme build --watch}` so its built files stay current.'
> Don't: 'Use runtime themes in production SSR apps; component overrides will flash on hydration.', "Import /built without the CSS file; component overrides won't apply.", 'Import package theme source into app runtime code.', 'Hand-edit the generated theme module; `theme add`, `theme remove`, and `theme use` regenerate it.'

#### Project rules — verbatim, .claude/CLAUDE.md:65

> - Theme: `astryx-themes.ts` is generated by `npx astryx theme add|use|remove`; do not edit it. Color mode is `light` / `dark` / `system` (default): `useThemePreference()` (`inertia/components/theme/theme_preference.tsx`) sets it, Astryx `useTheme().mode` reads the mode in effect. It is stored in the `app_theme` cookie, which the Edge shell applies as `color-scheme` before the app loads.

#### Decision

- Build: `npx astryx theme build src/themes/quran/quranTheme.ts` → `src/themes/quran/quran.css`, `quran.js`, `quran.d.ts`, `quran.variants.d.ts`. A build error is fixed in the source (Step 2), never in the output. Clear any "fonts not loaded" warning by matching family names to Step 5.
- Adopt, in order: `npx astryx theme add quran` → `npx astryx theme use quran` → `npx astryx theme remove neutral`. Afterwards `astryx-themes.ts` records only `quran` as default and imports `quran.js` + `quran.css` (and no Google-hosted `fonts.css`). Never touch that file by hand.
- `inertia/components/app_providers.tsx` — no change; it already reads `themes[defaultThemeSlug]`.
- `.oxlintrc.json` and `.oxfmtrc.json` (modified) — add `src/themes/quran/quran.js`, `src/themes/quran/quran.css` and `src/themes/quran/tokens/**` to `ignorePatterns` (generated output; `*.d.ts` is already ignored by oxlint — add the `.d.ts` files to oxfmt).
- Typecheck note: `Text type="arabic"` is typed through `quran.variants.d.ts`. If Step 8 does not typecheck, make the inertia program see it — e.g. add `../src/themes/quran/*.d.ts` to `inertia/tsconfig.json` `include`.

### Step 9 — Brand chrome: mark, name, favicon, browser color

Reads: design-system.md, frontend.md, edge-syntax.md

Harness rules: see Step 1 (design-system.md:15) and Step 8 (CLAUDE.md:21, :26).

#### Harness rules — verbatim, .flow/docs/edge-syntax.md:18-19, :129, :138

> - A tag occupies its own line, with nothing else on it. Mix text and `{{ }}` freely on other lines.
> - Close every block tag with `@end` — `@if … @end`, `@each … @end`, `@component … @end`. `@end` closes any block; do not reach for `@endif` / `@endfor` / `@endwhile`-style closers carried over from other template languages.

> - `{{ expression }}` — evaluate, **HTML-escape** the result, write to output. The default for every dynamic value.

> - `@if(expr)` / `@elseif(expr)` / `@else` / `@end` — conditional blocks; `expr` is any JS expression.

## Execution notes

Where the build departed from the steps above, and why:

- Step 1 — `neutralProfile` is `"custom"`, not Neutral's `"neutral-v1"`. `neutral-v1` forces chroma 0, so the sand seed came out pure gray; `custom` keeps the seed's hue and chroma.
- Step 2 — the palette import is `./tokens/quran.palette.js`: the backend program resolves with NodeNext. Neutral's `liftedSecondaryText` component overrides (item, tree-list-item, file-input, citation, segmented-control-item) are re-declared with sand stops, since Neutral writes them with its gray stops.
- Step 4 — after the visual check, light mode's `--color-background-surface` moved from sand 100 (pure white) to sand 95, and `--color-background-muted` to sand 90, so pages read on warm paper with white cards. The accent is emerald light 45 / dark 65; light 45 is the stop nearest the `#0F6B4F` seed.
- Step 6 — added `src/themes/css.d.ts` (`declare module '*.css'`) because the backend program also typechecks `astryx-themes.ts`, and a local theme's stylesheet has no package `exports` types. Added a `unicorn/filename-case: off` override for `src/themes/**`, because Astryx requires the `quranTheme.ts` stem.
- Step 10 — also replaced the starter subtitles on `auth/login.tsx` and `auth/signup.tsx` (no test asserts them). The signed-in dashboard is still the starter's empty state ("Your dashboard is ready"), which `auth/session.spec.ts` and `auth/signup.spec.ts` assert. Left for a follow-up because what that page should be is a product decision.
- `theme build` always prints "Fonts named but not loaded": the fonts load from `inertia/app.tsx`, which the build can't see. Every family name matches a loaded `@fontsource` face; this was confirmed in the browser (`document.fonts` shows Figtree Variable, Fraunces Variable and Amiri).
