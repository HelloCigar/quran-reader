# adonis-react-starter

A full-stack starter: an [AdonisJS 7](https://adonisjs.com) backend serving a React frontend through [Inertia](https://inertiajs.com), with UI built from the [Astryx](https://github.com/meta/astryx) design system. It comes with session auth (sign up, log in, log out), a dashboard shell, light and dark mode, browser tests, and fast lint and format tooling.

## What's included

| Area     | Stack                                                                                |
| -------- | ------------------------------------------------------------------------------------ |
| Backend  | AdonisJS 7, Lucid ORM on SQLite, VineJS validation, session auth                     |
| Frontend | React 19, Inertia, type-safe routing helpers from `@adonisjs/inertia/react`          |
| UI       | Astryx components with the neutral theme, StyleX for custom styles, Heroicons        |
| Build    | Vite 8, served by AdonisJS (`node ace serve` / `node ace build`)                     |
| Quality  | TypeScript, Oxlint and Oxfmt via [Vite+](https://viteplus.dev) (`vp lint`, `vp fmt`) |
| Tests    | Japa browser tests running in Playwright Chromium                                    |

Pages: a marketing home page, sign up, log in, a dashboard behind auth, a settings layout to build on, and custom 404 and 500 pages.

## Getting started

Requirements: Node.js 24 or newer, and npm.

```bash
npm install
cp .env.example .env
node ace generate:key        # fills APP_KEY in .env
node ace migration:run       # creates the SQLite database in tmp/
npm run dev
```

Open http://localhost:3333 and create an account.

## Project structure

```
app/                 Controllers, models, validators, middleware, exception handler
config/              App, auth, database, session, Inertia and other config
database/            Migrations (schema.ts is generated, don't edit it)
start/routes.ts      Routes
inertia/
  app.tsx            Client entry: Astryx styles and app providers
  pages/             One component per Inertia page, by domain (marketing, auth, app, errors)
  components/        Layouts, components and hooks, by domain (app, auth, marketing, settings,
                     navigation, theme, forms, feedback, brand, errors)
resources/views/     The Edge HTML shell
tests/browser/       Browser tests, one file per user flow
astryx-themes.ts     Theme module generated by the Astryx CLI
```

## Building the frontend

- **Components.** Pages are composed from Astryx components (`AppShell`, `Card`, `VStack`, `TextInput`, `Button`, ...). Browse them with `npx astryx search "<query>"` and read a component's props with `npx astryx component <Name>`. New pages can start from a template: `npx astryx build "<what you're building>"`.
- **Links.** Pass a URL from `urlFor('route.name')` to any Astryx link (`<Link href={urlFor('dashboard')}>`, `<Button href={...}>`). Links to app routes navigate with Inertia, without a full page load; external links stay normal links.
- **Forms.** `useRouteForm('route.name', initialValues)` types the form data from the route's validator and submits to that route. Spread `form.field('email')` onto an Astryx `TextInput` to bind its value and show the server's validation error under it.
- **Styling.** Use component props first. For anything else, write StyleX with `stylex.create()` using Astryx's typed tokens (`colorVars`, `spacingVars`, ... from `@astryxdesign/core/theme/tokens.stylex`) and pass it to a component's `xstyle` prop. Astryx's own styles ship prebuilt; only your StyleX is compiled, into cascade layers after Astryx's, so your styles win and themes still restyle components.
- **Theme.** The app follows the system's light or dark mode until the user picks one with the toggle; the choice is remembered in a cookie and applied before the page loads. To use another theme, install it and run `npx astryx theme add <slug>`.
- **Imports.** Import `Link`, `Form`, `router` and `useHttp` from `@adonisjs/inertia/react`, not `@inertiajs/react`. Lint enforces this.

## Testing

The tests drive a real browser through the app's user flows: signing up, logging in and out, auth redirects, navigation, the 404 page and dark mode.

```bash
npx playwright install chromium   # once per machine
npm test
```

The tests start the app on port 3333, so stop `npm run dev` first. They use their own database, `tmp/db.test.sqlite3`, which is migrated fresh on each run.

## Deploying

```bash
npm run build
cd build
npm ci --omit=dev
node bin/server.js
```

Set `NODE_ENV=production`, `APP_KEY` and the other variables from `.env.example` in the production environment, and run `node ace migration:run --force` against the production database.
